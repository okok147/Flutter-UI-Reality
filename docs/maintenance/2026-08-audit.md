# Maintenance audit — August 2026

Audit date: **11 August 2026**

Baseline: public `master` branch before the 2026 maintenance revival.

## Verified repository baseline

- 437 tracked files across five Flutter project directories.
- 157 GitHub stars and 50 forks at the audit date.
- No root license, automated workflow, security policy, issue forms, pull-request template, or published release.
- All five projects declared a Dart SDK upper bound below 3.0.0 and failed dependency resolution under Flutter 3.44.9 / Dart 3.12.2.
- Android scaffolding used API 28-era configurations, old Android Gradle Plugin and Gradle versions, and JCenter in multiple projects.
- Generated Flutter files, Eclipse metadata, macOS metadata, and conflict-backup files were tracked.
- Historical image and font provenance was incomplete.

The audit records the observed starting point; it does not infer historical maintainer intent or uninterrupted activity.

## Gardener findings and remediation

The baseline declared `font_awesome_flutter`, `floating_search_bar`, `outline_material_icons`, `material_design_icons_flutter`, and `cupertino_icons`. Most were unused or replaceable with Flutter platform widgets. The implementation also repeated gardener cards, used fixed-width layouts, contained an incorrect navigation callback, had a self-import in utilities, and retained an unrelated generated counter test.

The revival removes obsolete packages, uses a data-driven model and reusable card, adds responsive layouts and semantics, regenerates platform scaffolding, and replaces the counter test with behavioral widget coverage. CI validates formatting, static analysis, widget tests, and a release web build.

## Licensing and provenance decision

The MIT License covers repository-authored code and documentation, not third-party assets. Manjari includes an SIL Open Font License file. Several other font and visual assets lack complete provenance in Git history, so they are explicitly documented as historical material requiring review before reuse. Each legacy migration must either document, replace, or remove those assets.

## Validation boundary

The maintenance environment can verify the Gardener web release build. Android SDK and complete Xcode/CocoaPods toolchains were not available, so this audit does not claim Android or iOS builds passed. Current platform scaffolding is included so those builds can be validated in appropriate environments later.
